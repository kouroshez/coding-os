# Section Index — Historical Note

> P: Historical record of the retired per-file `<file>.INDEX.md` sidecar pattern.
> R: Investigating a residual `<file>.INDEX.md` sidecar in a consumer project, or understanding why an old reference points at a sidecar that no longer exists.
> S: Authoring a new doc — directory-level `00-index.md` is now the only navigation index.
> N: [docs-system.md](../governance/docs-system.md), [hooks-reference.md](hooks-reference.md)

> Nav: [Section Index](./00-index.md) | [Docs Index](../00-index.md)

## What this used to do

For every "fat" markdown doc (≥400 lines or ≥5 k tokens), the project once shipped a sidecar `<file>.INDEX.md` mapping H1/H2/H3 headings to anchor slugs, line ranges, and token estimates. An auto-regen hook (`auto-regen-section-index.sh`) rebuilt the sidecar on every Write/Edit. Agents were expected to read the sidecar (≈100–300 tokens) instead of the full doc.

## Why it was retired

The pattern was retired on 2026-05-08. Two reasons:

1. The directory-level `00-index.md` already provides cross-doc navigation via frontmatter, and that turned out to be enough for the agent flows we actually run.
2. The per-file sidecar created two SSOTs for the same intra-file structure (headings in the source doc, slug list in the sidecar). The sidecar drifted whenever a hook was skipped, which produced confusing slug mismatches in MCP tools that resolved against it.

## What replaced it

- Directory navigation: `docs/<dir>/00-index.md` (auto-generated by `scripts/regen_doc_index.py`).
- Heading lookups: read the doc's H2 list directly with `grep '^## '` against the live source.

## What you'll find in old projects

A consumer that pulled coding-os before 2026-05-08 may still have orphan `<file>.INDEX.md` files alongside their source docs. They are safe to delete — nothing reads them. Run:

```bash
find docs -name "*.INDEX.md" -type f -delete
```

A subsequent `cos sync-all` no longer regenerates them.
