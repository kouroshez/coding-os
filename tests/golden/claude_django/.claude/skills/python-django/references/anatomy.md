## 2. Layout map

| Pattern | Location | Naming | Imports from | Description |
|---|---|---|---|---|
| App package | `src/backend/<app>/` | `snake_case` | none | Self-contained Django app |
| App config | `src/backend/<app>/apps.py` | `apps.py` (literal) | `django.apps` | Registers app |
| Model | `src/backend/<app>/models/<entity>.py` | `<entity>.py` | `..base` | ORM entity |
| Serializer | `src/backend/<app>/serializers/<entity>.py` | `<entity>.py` | `..models` | DRF (de)serialization |
| ViewSet | `src/backend/<app>/views/<entity>.py` | `<entity>.py` | `..serializers` | DRF endpoint |
| URL | `src/backend/<app>/urls.py` | `urls.py` (literal) | `..views` | Router include |
| Service | `src/backend/<app>/services/<name>.py` | `<name>.py` | `..models` | Business logic, no I/O |
| Selector | `src/backend/<app>/selectors/<name>.py` | `<name>.py` | `..models` | Read-only queries |
| Admin | `src/backend/<app>/admin.py` | `admin.py` (literal) | `..models` | Django admin |
| Migration | `src/backend/<app>/migrations/NNNN_<slug>.py` | `NNNN_<slug>.py` | autogenerated | Schema change |
| Permission | `src/backend/<app>/permissions.py` | `permissions.py` (literal) | `rest_framework.permissions` | DRF guards |
| Test | `src/backend/<app>/tests/test_<name>.py` | `test_<name>.py` | source under test | pytest-django |
| Settings | `src/backend/config/settings/<env>.py` | `<env>.py` | `.base` | Per-env config |

## 3. Entity recipes

### Add a new endpoint

- **Trigger:** "add POST /api/users", "expose endpoint X".
- **Files:**
  1. `src/backend/<app>/views/<entity>.py`
  2. `src/backend/<app>/serializers/<entity>.py`
  3. `src/backend/<app>/urls.py` (extend router)
  4. `src/backend/<app>/tests/test_<entity>_views.py`
- **Steps:**
  1. ViewSet inherits from a project-base; never raw `APIView` unless required.
  2. Wire serializer; validate inputs at the serializer layer.
  3. Permission class set explicitly — never default-allow.
  4. Add OpenAPI/schema annotations (drf-spectacular).
  5. Test happy + 401 + 400 + 404 paths.
- **Generator:** [`src/scripts/new_endpoint.py`](../scripts/new_endpoint.py).

### Add a new model

- **Trigger:** "add User model", "new entity for X".
- **Files:**
  1. `src/backend/<app>/models/<entity>.py`
  2. `src/backend/<app>/migrations/NNNN_add_<entity>.py` (via `makemigrations`)
  3. `src/backend/<app>/tests/test_<entity>_model.py`
- **Steps:**
  1. Inherit from a project base model (UUID PK, timestamps).
  2. Add `__str__`, `Meta.ordering`, `Meta.indexes`.
  3. Run `python manage.py makemigrations <app>`; review the generated SQL with `sqlmigrate`.
  4. Tests cover constraints + cascade behavior.

### Add a new service

- **Trigger:** "extract this logic from the view into a service".
- **Files:**
  1. `src/backend/<app>/services/<name>.py`
  2. `src/backend/<app>/tests/test_<name>_service.py`
- **Steps:**
  1. Pure functions on top of models; no HTTP, no Celery direct.
  2. Selectors stay read-only; services own writes + side effects.
  3. Raise typed exceptions; views map them to DRF responses.

### Add a new migration

- **Trigger:** schema change.
- **Files:**
  1. `src/backend/<app>/migrations/NNNN_<slug>.py`
- **Steps:**
  1. Append-only — never edit a past migration.
  2. Data migrations carry both `forwards` and `reverse` ops.
  3. Test on a copy of prod data when the migration touches >1M rows.

### Add a new test

- **Trigger:** any new view / model / service requires tests.
- **Files:**
  1. `src/backend/<app>/tests/test_<name>.py`
- **Steps:**
  1. pytest-django with `db` fixture; factories from `factory_boy`.
  2. Given/When/Then; cover happy + at least one failure path.
  3. Mocks at the boundary (HTTP, email, Celery), real DB inside.

## 4. Conventions

#### Naming

- Files / packages: `snake_case`.
- Classes: `PascalCase`.
- Functions / variables: `snake_case`.
- Constants: `SCREAMING_SNAKE_CASE`.
- Tests: `test_<thing>.py` mirrored under `<app>/tests/`.

#### Test colocation

Mirrored. Tests live under `src/backend/<app>/tests/test_<name>.py` — never colocated next to models or views. Reason: Django test runner discovery + factory reuse.

#### Dependency rules

- ✓ `src/backend/<app>/` may import from `src/backend/<app>/` siblings + `src/backend/config/`.
- ✓ Cross-app imports OK only via published `services/` and `selectors/`.
- ✗ Views may NOT call other apps' models directly — go through services.
- ✗ Models may NOT import from views or serializers.
- ✗ `src/backend/` may NOT import from `src/frontend/`, `src/mobile/`, `src/ai-service/`.
